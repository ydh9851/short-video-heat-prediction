# 阶段 4：论文与答辩证据 — 需求说明（spec）

## 1. 背景与目标

根目录 `项目代码审查与完善方案.md` 的阶段 0~3 已完成（阶段 3 于本次收尾）。阶段 4 的目标是把系统已有的工程与算法能力**沉淀为可交付的论文素材与答辩证据**：

- 论文能直接引用的四类文档（需求与用例、概要设计、数据库设计、测试报告、部署手册）；
- 可复现的测试证据（后端单测、算法单测、接口契约与安全断言、性能实测命令）；
- 5 分钟答辩演示脚本，与阶段 3 新增能力（命令面板、演示导览、EDA 交互洞察、大屏）对齐。

**约束**：本阶段只新增 `docs/` 下的文档与必要的事实核对，不改动业务代码；所有数字必须可追溯（标明来源文件/命令），无法在本机实测的项目明确写「执行命令 + 需在完整环境运行」，不得编造。

## 3. 事实核对要求（写作前必须确认）

- 后端测试：`mvn test` 43 条（10 个测试类，已实测全绿）；逐类统计来自 `backend/target/surefire-reports`。
- 算法测试：`pytest algorithm/tests` 47 条（已实测 0.75s 全绿）。
- 数据：样本量 / 类别数 / 时间跨度取自 `data/processed/dataset_registry.json`；质量门禁取自 `data/processed/quality_report.json`；模型版本取自 `data/models/model_registry.json`。
- 表结构：以 `backend/src/main/resources/db/migration/V1~V7` 为准，不照抄旧 `sql/*.sql`。
- 部署：以 `deploy/docker-compose.yml`、`Dockerfile.*`、`.env.example` 为准。
- 性能：用本地 `.venv` 实测 Python 单条预测 CLI 冷/热耗时（3 次取中位）；批量 500 / 45 万行导入因需完整环境，只给命令与预期判定口径。

## 4. 验收标准

- 五份文档 + 演示脚本齐全，交叉引用路径有效，无占位符（TODO/XXX/待补）。
- 文档中的每个指标/表名/端点均能在仓库中找到出处。
- `docs/API.md` 的分组与 `controller` 包一致（允许说明「同步/异步」差异）。
- `README.md` 增加「文档导航」区块，可一键进入 docs。
- 不改动 `backend`、`algorithm`、`frontend` 源码；`mvn test` 与 `pytest` 仍全绿。

## 5. 不做清单

- 不新增业务功能、不改 UI；
- 不在本机启动完整 Docker Compose（避免长时间占用环境）；部署手册只写步骤与验证方法；
- 不代跑 3~5 人用户测试，只交付问卷模板与记录表；
- 不重写论文正文，只交付论文可直接引用的素材。
