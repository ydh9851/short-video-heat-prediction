# 需求与用例

> 本文是毕业论文「系统需求与分析」章节的素材，所有需求均可追溯到页面与接口。
> 接口前缀与分组见 [API.md](./API.md)，表结构见 [数据库设计.md](./数据库设计.md)，架构见 [概要设计.md](./概要设计.md)。

## 1. 系统定位

本系统面向**短视频内容运营**场景：在视频发布时即可获得先验信息（视频类别、作者粉丝数、发布时段）的前提下，给出**热度预测值、热度等级、可解释归因与可执行建议**，并把数据治理、实验复现、模型治理整合为同一平台。

设计原则：

1. **预测必须可用**：只使用发布时可得信息，播放/点赞/评论/转发/收藏不进入特征，避免数据泄漏。
2. **结论必须可解释**：预测结果必须能拆解到特征（SHAP），并给出反事实建议。
3. **过程必须可复现**：任何页面数字都应能在「实验中心」重跑，并可在实验台账中追溯。
4. **模型必须可运营**：模型版本、阶段、影子对比、上线预演与回滚形成闭环。

## 2. 角色

| 角色 | 说明 | 权限边界 |
|---|---|---|
| 访客（未登录） | 只能访问登录页与静态资源 | 所有业务接口返回 401（默认拒绝） |
| 普通用户 | 内容创作者 / 运营人员 | 预测、归因、分级、数据查看、实验提交与查看、场景、报告；访问 `/api/admin/**` 返回 403 |
| 管理员 | 平台维护者 | 在普通用户基础上，增加用户管理、消息、任务中心、操作审计、系统状态、模型治理（同步/上线/回滚/漂移/预演） |

权限实现：Spring Security 默认 `anyRequest().authenticated()`，白名单仅登录与错误页；管理接口额外要求 `ADMIN` 角色。前端路由守卫拦截未登录跳转。

## 4. 核心用例

### UC-01 单条热度预测并查看区间

- **参与者**：普通用户
- **前置条件**：已登录；模型已训练（首次调用可自动训练）。
- **主流程**：
  1. 进入「热度预测」，选择视频类别，拖动粉丝数与发布小时滑杆；
  2. 提交预测，系统返回热度点预测、log 值、热度等级与模型版本；
  3. 用户点击「计算 90% 区间」，系统返回保形区间与分位数区间；
  4. 页面展示决策卡（结论、区间、不确定性、建议、风险）。
- **异常流程**：
  - 发布小时越界（<0 或 >23）→ 返回 400，页面提示参数非法；
  - 常驻推理服务不可用 → 网关自动降级为 CLI，仍返回结果；
  - 模型不可用且训练失败 → 返回可读错误，不产生 500 堆栈。
- **后置条件**：预测记录写入 `t_heat_predict_log`。
- **对应端点**：`POST /api/predict`、`POST /api/predict/interval`。

### UC-02 归因解释并生成报告

- **参与者**：普通用户
- **前置条件**：已有预测输入（可来自场景或手动输入）。
- **主流程**：
  1. 进入「归因分析」，查看全局 SHAP 重要性；
  2. 输入单条样本，查看 Top-K 贡献与瀑布图；
  3. 查看反事实建议与解释可信度徽标（紧凑性 / 一致性 / 稳定性）；
  4. 点击「生成报告」，报告中心异步生成自包含 HTML；
  5. 生成完成后可下载、分享（生成令牌）或免登录只读访问。
- **异常流程**：场景不存在 → 404；参数非法 → 400；生成失败 → 报告状态 FAILED 并记录原因。
- **后置条件**：`t_report` 落库，文件位于 `data/reports/`。
- **对应端点**：`/api/attribution/**`、`POST /api/report/generate`、`GET /api/report/{id}/content`。

### UC-03 运行一个可复现实验

- **参与者**：普通用户
- **前置条件**：算法引擎可用（容器或本地）。
- **主流程**：
  1. 进入「实验中心」，选择实验模式（如交叉验证）；
  2. 提交实验，后端立即返回 taskId，任务进入 QUEUED → RUNNING；
  3. 前端轮询任务状态并展示进度条与已耗时；
  4. 完成后展示指标、图表与一句话结论（含 traceId）；
  5. 实验自动记入台账，可与历史实验两条对比。
- **异常流程**：引擎超时 → 任务 FAILED 并记录错误；重复提交 → 各自独立任务。
- **后置条件**：实验台账新增记录；结果可供业务页面 `latest` 引用。
- **对应端点**：`POST /api/evaluation/submit`、`GET /api/evaluation/task/{taskId}`、`GET /api/evaluation/runs`。

### UC-04 模型上线预演与回滚

- **参与者**：管理员
- **前置条件**：存在 staging 候选版本。
- **主流程**：
  1. 在模型治理页选择候选版本，点击「上线预演」；
  2. 系统在真实采样上并行打分，输出平均/P50/P90/最大绝对偏差、相关系数、头部重合度；
  3. 预演通过后执行 promote，`active` 指向新版本；
  4. 预测接口返回的 `modelVersion` 变为新版本；
  5. 若线上异常，执行 rollback 回到上一 production 版本。
- **异常流程**：预演未通过或线上版本已变化 → 拒绝上线并提示原因；参数错误 → 400。
- **后置条件**：`t_rehearsal_report` 落库；`model_registry.json` 更新阶段。
- **对应端点**：`POST /api/models/{model}/rehearsal`、`POST /api/models/{model}/promote`、`POST /api/models/{model}/rollback`。

## 5. 非功能需求

| 类别 | 需求与验收口径 |
|---|---|
| 性能 | 单条预测（CLI 冷启动）≤ 3 s；常驻推理服务目标 ≤ 100 ms；批量 500 条一次性提交；数据导入不阻塞其他请求（任务化） |
| 安全 | 默认拒绝：匿名业务接口 401，普通用户管理接口 403；密码 BCrypt 哈希存储；传输敏感字段 RSA；CORS 白名单；登录接口限流 |
| 可观测 | 每个请求携带 `X-Trace-Id`，可串联 Java 与 Python 日志；Prometheus 指标可抓取；管理操作写入审计表 |
| 可复现 | 实验参数、耗时、traceId、结果全部入台账；模型版本含数据版本与特征版本快照 |
| 可用性 | 引擎不可用时自动降级 CLI；关于页/登录页数字在接口失败时回退缓存与默认值；空数据、加载中、错误态均有对应组件 |
| 可维护 | 前后端统一响应结构 `{code,message,response}`；异常码集中管理；数据库变更走 Flyway |
| 合规 | 数据集为 Kaggle 公开数据（Apache-2.0），页面标注来源；不使用用户隐私数据 |
